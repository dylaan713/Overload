# Log (Plan B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Log placeholder with the screen Dylan uses after every set: one exercise at a time, target beside last time, difficulty words instead of RIR, a Next-exercise picker that shows what's short this week, and a draft that survives app switches and reloads.

**Architecture:** Pure helpers in `src/domain/difficulty.ts` and `src/domain/log.ts` (no React) decide difficulty mapping, which day the Log shows, set append/edit/remove/restore, prefill and coaching (engine calls on the doc **without** the Log's day). `appStore` gains set actions over those helpers through its existing commit queue; `uiStore` gains the persisted Log draft. `src/features/log/` renders it with Plan A primitives and motion. The engine (`src/domain/engine/`) is not modified.

**Tech Stack:** React 19, TypeScript strict, Zustand vanilla, `motion@13.5.1`, CSS Modules + tokens, Vitest + Testing Library + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-18-log-design.md` (approved 2026-10-18). Also the engine spec `docs/superpowers/specs/2026-10-17-training-engine-design.md` and Plan A's Global Constraints (`docs/superpowers/plans/2026-10-09-ui-foundation.md`), which all still apply.

## Global Constraints

- Plan A's Global Constraints apply unchanged (tokens, ≥13px text, 16px inputs, ≥44px targets, springs from `src/ui/motion.ts`, reduced motion → fades, Undo over confirmation, gate before every commit, commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, branch `rewrite`, don't touch `src/App.jsx` / `index.html` / `src/storage.js` / `src/index.css` / `src/domain/engine/`).
- **No stored-doc shape change.** Sets are `SetEntry { weight, reps, warmup, rir, orig? }` in `Block { id, exerciseId, test, sets }` in `Session { id, date, name: "", blocks }`. Editing a set's weight clears `orig`.
- **Difficulty words** (exact): `Easy`, `Moderate`, `Hard`, `All out`. Stored `rir`: Easy 4, Moderate 2, Hard 1, All out 0. Reading: 4 → Easy, 2–3 → Moderate, 1 → Hard, 0 → All out. Range "{word(rirHigh)}–{word(rirLow)}", one word when both map to the same word. The UI never shows RIR numbers.
- **Targets are fixed for the day:** `targetsFor`, Last time and `fatigueSuggestion` run on the doc with the Log's day removed. `weeklyVolume` runs on the full doc. Every engine call uses the Log's day as `today`.
- **Log's day:** today's local date, unless the latest logged set was < 3 h ago and its session still exists → that session's date.
- **Draft:** saved to `overload.v2.ui` on every change (debounce ≤ 250 ms), flushed on `visibilitychange` → hidden and `pagehide`; restored silently; dropped when its day ≠ the Log's day. Never in backups.
- Exact copy: "Log set", "＋ Next exercise", "Set {n} of {m}", "last set {m:ss} ago", "Warm-up", "Start with any exercise", "Still short this week", "Every muscle you train is on track this week", "Add from the library", "First time: pick a weight you could do for {repLow} reps", "Most lifts were down this week — take a lighter week?", "Accept", "Dismiss", "Test day", "Test day is chosen before your first working set", "Editing set {n}", "Save", "Cancel", "Delete set", "Removed set {n}", "Undo", "Aim for".

## Review Focus

1. **The page unloads within the debounce window right after a keystroke** (iOS kills the PWA while Spotify opens): the typed text must come back exactly (Task 4).
2. **Undo after removing the only set of the only exercise of the day:** the session comes back with the same ids, date and position; and Undo after another set was logged in the meantime re-inserts at the original index without losing the newer set (Tasks 2, 8).
3. **A save fails while logging a set:** the typed weight/reps/difficulty stay in the entry row, no set appears, the counter doesn't restart, and the save-error alert shows (Task 6).
4. **A workout across midnight:** last set 23:30, open at 00:40 → same session and same targets; open at 02:31 → a new empty day and yesterday's draft is dropped (Tasks 2, 4).
5. **The current exercise is archived or permanently deleted from Settings mid-workout:** archived → still current and loggable with its sets; deleted → its sets are gone (cascade), the draft's exercise is cleared and the Log falls back to the next chip or the empty state without crashing (Task 6).

### Task 2: Log domain helpers

**Files:**
- Create: `src/domain/log.ts`, `tests/domain/log.test.ts`

**Interfaces:**
- Consumes: `targetsFor`, `LiftTargets` (engine), `liftHistory`, `LiftSession`, `fatigueSuggestion`, `StoreDoc` types.
- Produces:
  - `type SetRef = { day: string; blockId: string; index: number }`
  - `type RemovedSet = { day: string; session: Session | null; sessionIndex: number; blockIndex: number; block: Block; index: number; set: SetEntry }` — `session` is the whole removed session when the removal emptied it (else `null`); `block` is the block as it was before removal.
  - `logDayFor(doc: StoreDoc, today: string, now: number, last: { day: string; at: number } | null): string` — `LOG_DAY_GRACE_MS = 3 * 60 * 60 * 1000`.
  - `sessionOn(doc, day): Session | undefined`; `blockFor(doc, day, exerciseId): Block | undefined`
  - `withoutDay(doc, day): StoreDoc`
  - `appendSet(doc, input: { day: string; exerciseId: string; set: SetEntry; test: boolean }, newId: () => string): StoreDoc` — creates the session (`name: ""`, sessions kept sorted by date) and block (appended) when missing; never a second block for the same exercise that day.
  - `replaceSet(doc, ref: SetRef, set: SetEntry): StoreDoc` — drops `orig` when `set.weight !== old.weight`, keeps it otherwise.
  - `removeSet(doc, ref): { doc: StoreDoc; removed: RemovedSet } | null` — removes the block when emptied, the session when its last block goes.
  - `restoreSet(doc, removed: RemovedSet): StoreDoc` — re-inserts at `removed.index` (clamped), recreating block (at `blockIndex`) / session (at `sessionIndex`, same ids) if gone.
  - `setTestFlag(doc, day, exerciseId, test): StoreDoc | { error: string }` — error "Test day is chosen before your first working set" if the block has a working set.
  - `canTest(ex: Exercise): boolean` — `loadKind === "external" && equipment !== "band"` (mirrors the engine).
  - `coachFor(doc, exerciseId, day, test: boolean): { targets: LiftTargets; last: LiftSession | null }` — both from `withoutDay(doc, day)` with `today = day`.
  - `prefill(targets: LiftTargets, block: Block | undefined, warmup: boolean): { weight: number | null; reps: number | null }`:
    - warm-up mode: the next ramp entry `targets.warmups[k]` (k = warm-ups logged); past the ramp, the last logged warm-up; none → nulls.
    - working: `targets.sets[k]` (k = working sets logged; beyond the count, the last target set); weight = test-day `targets.ladder[k]` (reps 1) else `targets.weight`; when `targets.weight` is null (first time), the last logged working weight or null.
  - `setCount(targets): number` = `targets.sets.length`.

- [ ] **Step 1: Write the failing tests** (`log.test.ts`, using `tests/helpers/build.ts`):

  - appendSet: on an empty doc creates one session dated `day` with `name ""` and one block; a second set for the same exercise appends to that block; a different exercise gets a second block; `test` is copied onto a new block only.
  - replaceSet: changing weight drops `orig`; changing only reps keeps it.
  - removeSet/restoreSet round trip deep-equals the original doc for: a middle set; the only set of a block among others; the only set of the only block (session removed and restored with its id and position between two other days).
  - restoreSet after another set was appended to the same block re-inserts at the original index and keeps the new set.
  - setTestFlag: allowed with only warm-ups logged; refused with the exact message once a working set exists.
  - coachFor ignores the day: with history `day("2026-10-10", [["a", sets(100,[10,10,10])]])` and today's `day("2026-10-18", [["a", sets(100,[6])]])`, `coachFor(doc,"a","2026-10-18",false)` equals `targetsFor(withoutDay(...))` and `last.date === "2026-10-10"`.
  - prefill: warm-up mode walks the ramp then repeats the last logged warm-up; working mode walks `targets.sets` then repeats the last; first time uses the last logged working weight; test day uses ladder weights with reps 1.
